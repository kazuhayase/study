## 運用ノウハウ（次回同種作業向け）
- サブエージェントは長時間PDF読取でストール（600s watchdog）やセッション上限で頻繁に落ちる。
  **SendMessage で同じ agentId に再開指示すれば文脈を保持したまま続行できる**（transcript が消えている場合は新規起動し、
  sources.yaml の article_index 経由で調査結果を引き継ぐ）。
- 検証は「範囲限定の確認ラウンド」（前ラウンド指摘の是正確認のみ、PASS済み再照合なし）にするとトークンを大幅節約できる。
  ただし全数再照合すると毎回新しい軽微指摘が出る傾向（逐語引用の「等」「例えば」レベル）。
- 起草を Opus→Sonnet に変えてもverifier が品質を担保するため最終水準は不変。修正ラウンドが1回程度増えるがトータルでは安価。
- 横断監査は「grep で全タグ抽出→Python で機械検算（ページオフセット・取得日有無・字数）→ドライラン付き一括修正スクリプト」
  の3段構えが有効。verified 済み本文の実質改変（字数圧縮等）は再検証が必要になるため監査フェーズではやらない。
